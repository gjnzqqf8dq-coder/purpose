# Purpose の理想像（本人の口述を原稿化・2026-09-11）

## 一文で
**Purpose と Claude Code だけを触っていれば、すべてのタスクが片づく状態。** 前段階の説明も、面倒な分解も、私はしない。

## 流れ
1. Purpose の「新しいゴールを壁打ちする」を押す → Claude Code に遷移し、プロンプトは入力済み。送信するだけ
2. Claude Code はすぐ逆質問を始める。目標、そこまでの構造、定量的に何を達成すれば近づくか、を分解していく
3. 解像度 **100%** まで終わらない。100% ＝ 目標が構造分解され、末端の「次にやること」が、AI がそのまま実行できるほど細かく一つずつ決まっている状態
4. 100% になったと Claude Code が判断したら、Purpose の入れ子（ゴール → 中の目標 → タスク）に全部書き込む（Purpose では data.json への書き込み＋push で実現。MCP や Computer Use は要らない）
5. 私はそれを一つずつこなす

## 各層に「AIと一緒にこなす」
- ゴール／中の目標／タスク、どの層にもボタンがある。押した層が、その回の作業の粒度
- 押すと Claude Code に遷移し、**上位ゴールからそのノードまでの文脈が全部入った長文プロンプト**が入力済み。私が前段階を説明することは無い
- 完了条件は定量的に決まっているので、AI は終わったら自分で判断し、Purpose のチェックを付ける（done:true を書いて push）
- 抽象度が高い層ほど AI の精度は落ちる。だから「アイデアだけ先に考えたい」なら、その層を押す。どこまでの抽象・具象で並走させるかは私が選ぶ

## AI 側に求める姿勢（自律・並走）
- Claude Code なので、Computer Use・スキル・Notion 閲覧・ファイル操作など、あらゆる手段を自分で選んで使う。毎回私が指示しない
- 「めんどくさい」と感じる瞬間（アイデアを出す、一つずつ考える、前提を入力する）を私に残さない
- その代わり、逆質問で私の判断だけを取る。「こういう時はどうやるのがいい？」「良いアイデアの条件は？」「これを分解するとこうだが合っているか？」— こう聞かれると楽で、やりやすい
- 大きい目標を見失わず、ずっと私と壁打ちし続ける規律を持つ

## Purpose の方針
- 問題解決に特化した、シンプルでスタイリッシュな道具。Addness にある「作業場」系の機能（チャット・通知・メンバー・CRM・数値・録画…）は要らない
- 入力 UI は最小。ゴールは壁打ちで生まれ、タスクは AI が置く。私はチェックとスワイプと期日の3択だけ
- 月3,000円の Addness より、自分で Claude Code で作るほうが良いものになる
